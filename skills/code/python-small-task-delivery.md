# Skill：python-small-task-delivery

**Name:** python-small-task-delivery

## When to use / 触发条件
- 用户让写一个小的 Python 片段、函数或脚本，常见说法：
  - “只给代码”“一行代码”“只回复代码”；
  - “写个函数/工具，并说明它是干什么的”“记下来”；
  - 小工具、示例函数、需要用 doctest 验证的练习。
- 只适用于本机可完成、无第三方依赖的小任务；大型项目另走项目流程。

## Steps / 步骤
1. **先判断交付形态**
   - 只要代码：不建文件、不跑工具，直接给一个最小代码块，代码块外不写解释。
   - 要文件/函数：进入下一步。
2. **看工作目录，先读后改**
   - 目标文件已存在时，先用 `read` 读它；已经满足需求就只做验证，不要重写。
   - 需要补充内容时用 `edit` 做最小修改，不要覆盖用户已有实现。
3. **写文件时至少包含三层说明**
   - 模块级 docstring：一句话说明文件用途；
   - 函数 docstring：用途、参数、返回值；
   - 2 个以上 doctest 示例（`>>> add(2, 3)` 的下一行写 `5`），让“记下来干什么的”同时变成可执行测试。
4. **一次 bash 调用里验证**
   - 跑 `python3 -m doctest -v <file>.py`；
   - 再跑一段断言，覆盖正常值、0、负数、浮点数；
   - 失败就修，修完重跑，不要只跑一次就宣布完成。
5. **简要汇报**
   - 文件路径、函数用途一句话、测试通过情况。
   - 不要主动加 pytest 文件、README 或额外依赖，除非用户明确要求。

## Example / 示例
用户：“写一个 Python 函数 add(a, b) 返回两者之和，并记下来这个函数是干什么的”

`add.py`：
```python
"""简单加法工具。"""


def add(a, b):
    """返回 a 与 b 的和。

    用途：计算两个数（int/float 等）的和，等价于 a + b。
    参数：a 第一个加数；b 第二个加数。
    返回：a + b 的结果。

    示例：
        >>> add(2, 3)
        5
        >>> add(1.5, 2.5)
        4.0
    """
    return a + b
```

验证：
```bash
python3 -m doctest -v add.py && python3 -c "from add import add; assert add(2,3)==5 and add(-1,1)==0 and add(1.5,2.5)==4.0"
```

## Notes / 注意事项
- 不要为了“展示工作量”创建 README、test_add.py 或清理 `__pycache__` 等无关文件。
- 已有文件先读后改；不要覆盖用户已有实现。
- 用户说“只给代码”时，代码块外不要写“这是代码”等废话。
